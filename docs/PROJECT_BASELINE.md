## Stack and application boundaries

- JavaScript/ES modules, Next.js App Router `16.4.3`, React/React DOM `19.3.1`, React Flow `@xyflow/react` `12.12.0`, iron-session `9.0.1`, ipaddr.js `2.5.0`, fflate `0.8.3`, @xmldom/xmldom `0.9.12` and Playwright `1.62.1`; versions are from `package.json`. Local tooling reported Node `26.2.0` and pnpm `11.25.0`. Inter and JetBrains Mono download at build time through `next/font/google`. CSS uses semantic dark/light tokens.
- `app/page.js` hosts a client workbench with view/tab navigation. `/login`, `/logout` and `/redactor` are separate routes. `WorkflowBuilder` owns React Flow state and invokes the browser-side `workflowEngine`; live adapters call same-origin Node routes. Inputs and action results pass through client run state.
- Browser localStorage holds agents, workflow versions, saved sources, runs, approvals, query data, settings/calendar and Architect chat. Server process globals hold schedules, webhook buffers, Architect telemetry, and MCP audit records. Upstash Redis REST is used for session/rate-limit security state. There is no general application database, durable event queue, worker, artifact/object store, workflow credential vault, or enforced tenant boundary in this checkout.
- `proxy.js` guards `/` and `/redactor`; `lib/security/route.mjs` independently wraps API handlers with role/scope permissions, origin/CORS checks, limits and safe error handling. `lib/security/egress.mjs` restricts and bounds server outbound HTTP. `next.config.mjs` applies security and cache headers and a network-blocking redactor document/worker policy. Client reviewer names and team records are local presentation data. There is no SSO or MFA in the current auth flow.

## Production login failure

`proxy.js:7–8` calls `authConfig()` before handling cookies or Redis and returns the observed plain-text 503 on failure. `lib/security/auth.mjs:14–30` requires canonical `GRA_APP_ORIGIN` (production value `https://gra-agent-workbench.vercel.app`, no trailing slash), `GRA_SESSION_PASSWORD` with at least 32 characters, `GRA_AUTH_USERS_JSON` with 1–50 valid principals (unique IDs/emails, admin/operator/viewer role, positive integer version and supported salted scrypt hash), and valid `GRA_SERVICE_TOKENS_JSON` if set. A malformed optional token entry can block browser access too. An exact failed field cannot be identified from the response. `/api/auth/login` also calls `authConfig()` and can emit `AUTH_NOT_CONFIGURED`. Once config passes, bad/missing Redis produces `SECURITY_STORE_UNAVAILABLE` in APIs and a page-session redirect can conceal that second-stage failure.

On the owning Vercel team, locate the project by the exact domain under **Settings → Domains**. Record project and team IDs, current production deployment SHA/source, connected repository and production branch under **Settings → Git** or **Environments → Production**, and root/framework/Node/install/build settings under **Build and Deployment**. Verify **Settings → Environment Variables** for production scope, exact origin, those auth inputs, `GRA_SECURITY_STORE=redis`, `GRA_REDIS_REST_URL` (supported HTTPS Upstash REST root endpoint) and `GRA_REDIS_REST_TOKEN`. Validate JSON and secret length privately; inspect logs and status codes without printing values. The user creation helper is `scripts/create-auth-user.mjs`. Once authorized, apply fixes to the existing project and issue a new production deployment there so the new variables take effect. Confirm protected-page redirect and anonymous session denial, then sign-in, logout, expiry, viewer/operator/admin denials and shared-store behavior using synthetic accounts. Use same-project protected preview for negative configuration checks if available. [Vercel environment variables](https://vercel.com/docs/environment-variables) · [Vercel Git deployments](https://vercel.com/docs/git).

Feature-only environment inputs include `GRA_HTTP_ALLOWED_HOSTS`, `GRA_INTEGRATION_ORIGINS`, `GRA_ENABLE_SYNTHETIC_AUDIT`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY`, `RESEND_API_KEY`, `RESEND_FROM_EMAIL` and `RESEND_REPLY_TO`. `NEXT_TELEMETRY_DISABLED` is a tooling option.
